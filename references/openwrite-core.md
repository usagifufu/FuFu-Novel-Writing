# Openwrite 方法论落地（Openwrite Core）

来源：Openwrite 项目的核心思想——**长篇小说不是一次性 prompt，而是一套可重复、可审计的工程流水线**。本文件说明如何把它落地到本技能的工作流里。

## 1. 规划写作分家（双 Agent 模式）

Openwrite 把"定方向"和"写正文"分成两个角色，互不越权：

- **规划者（Goethe）**：负责意图路由、创作罗盘、大纲、伏笔 DAG、章节任务书；产出是"方案 + 已批准事实"，不是正文。
- **写作者（Dante）**：只接收任务书与 canonical packet，按已批准事实写正文；写作中发现问题退回规划者，不自行改大纲。

同一会话内的落地方式：

- 先独立完成规划（罗盘 → 大纲 → 本章任务书），全部获批后再进入正文。
- 写作中产生的结构性问题（剧情走不通、人设冲突）**不边写边改**：记录为阻塞项，回到规划环节解决。
- 若用户开启多会话/多 Agent，可以让规划与写作分别在独立任务里进行，通过文件交接。

**显式交接（handoff）**：规划成熟（罗盘、大纲、伏笔 DAG、本章任务书全部获批）后，不是口头说"可以写了"就结束，而是把交接物落盘：`plot/author_intent.md`（作者意图与约束）与 `plot/current_focus.md`（当前焦点）写好后随每章 canonical packet 进入写作上下文；写作角色开工前先读交接物，只按已批准事实执行，交接后规划侧不再改动已批资产。

**风格三模式**：文风卡按来源定档，写作前先选定模式并写入 `lorebook/风格卡.md` 头部，每章 Brief 注明当前模式，避免混用漂移：

- `generic`：只用内置通用中文网文规则（没有样本时的保底风格）。
- `extracted`：仅用用户样本提取的风格规则（见 [style-learning.md](style-learning.md)）。
- `hybrid`：通用规则与提取规则按主次合成（默认推荐）。

## 2. 创作罗盘（Compass）

罗盘是全书的方向锚，防止长跑中跑偏。文件固定为 `plot/罗盘.md`，包含四栏：

| 栏位 | 含义 | 判据 |
| --- | --- | --- |
| 长期承诺 | 本书不可动摇的核心（主题、主角弧光、核心关系、最终悬念） | 违背它 = 烂尾/崩人设 |
| 近期焦点 | 当前卷/近十章要推进的目标 | 当前阶段所有章节都应服务它 |
| 必须保留 | 读者已经记住、不能撤回的元素（关键物件、已兑现承诺、已成事实） | 改动需用户明确批准 |
| 必须避免 | 破坏体验的红线（OOC 行为、设定冲突、无回报拖戏） | 写作指令中的禁写事项来源 |

使用规则：

- 每次开写（规划或动笔）前重读罗盘；与罗盘冲突的灵感先写入待办，不改罗盘。
- 章节任务书里必须有"罗盘对齐"一栏，说明本章服务哪个近期焦点、守住哪些长期承诺。
- 罗盘本身也要复审：每卷结束或明显跑偏时，由用户决定是否更新，改动记入 `plot/decisions.md`。

## 3. 单一真源与运行态分离

每一条事实只有一个确认版，防止"同一件事两个说法"：

- **src（确认版）**：已批准、不会再被推导覆盖的内容——`lorebook/`、`plot/`、`manuscript/` 中已定稿的部分。
- **运行态（data）**：随剧情推导变化的内容——`world-state/`（时间线、主体、历法、提交链）。

规则：

- 写正文时从运行态查事实，从 src 查设定；两者冲突时先列冲突、由用户裁决，AI 不得自行改 src。
- 运行态只追加（事件溯源），不回改历史；状态修正用新切面表达。
- 任何对 src 的修改走**确认门**（见下）。

**世界关系图谱**：人物、势力、物件之间的关系共用单一真源（建议 `lorebook/relations.md` 或 `world-state/relations.md`），不分散在各角色卡里各写一份；增删改一律走确认门：diff 预览 + 同一 `base_revision` 确认，revision 冲突时重新生成预览再确认，防止多会话同时改图谱互相覆盖。

**单源文档规范**：核心设定文档统一用 **TOML front matter + Markdown 正文**。front matter 记录 `id`、`summary`（一句话摘要）、`tags`、`detail_refs`（指向更细文档的路径列表）、`related`（关联文档 id）；正文只写该文档独有内容，重复内容一律引用不复制。这样同一事实只有一处确认版，检索与联动修改都有稳定锚点。

## 4. 确认门（Diff Gate）

所有会改变已批准资产的操作（改设定、改大纲、改已定稿正文、改罗盘）必须先走：

1. 生成 **diff 预览**：旧内容 → 新内容，标出改了什么、为什么改。
2. 用户确认后才落盘。
3. 落盘后同步受影响的下游文件（承诺账本、时间线、提交链）。

AI 不得静默改写已批准内容；"建议修改"和"已经修改"之间永远隔着用户确认。

### 增量修改协议（大纲与图谱）

改大纲或关系图谱时禁止整篇覆写，用**精确补丁**：

1. 定位：以 `old_text -> new_text` 给出被替换的确切片段与替换内容，不整段重写。
2. 预览：先展示 diff（旧 → 新、改了几处、为什么改），用户确认后才落盘。
3. 防冲突：补丁带 `revision` 编号，落盘前比对 `base_revision`；已被其他会话改过则重新生成预览再确认。
4. 安全重编号：涉及章节/伏笔编号的改动，只对**尚未写正文**的后续项重编号；已写正文的章节保持原编号，用追加说明迁移，避免全书章节号漂移。

## 5. Canonical Packet（本章上下文组装包）

每章写作只喂一个稳定的最小上下文包，保证每次续写不漂移、不超载：

```markdown
## 第 N 章 Canonical Packet
1. 当前章大纲窗口：structure.md 中本章及前后 1-2 章要点
2. 相关角色卡：本章出场角色（lorebook/characters/）
3. 世界规则：本章涉及的力量体系、地点、势力规则
4. 伏笔状态：promises.md 中与本章相关承诺的当前状态
5. 上一章正文与摘要：有界章节记忆（见下）
6. 真相文件：world-state/timeline.md 的相关切面
7. 风格卡：lorebook/风格卡.md
8. 创作罗盘：plot/罗盘.md（对齐栏）
```

组装原则：**只装本章需要的最小集合**；同一事实以单一真源为准；装不下的细节留文件路径，用时再查。

## 6. 有界章节记忆（Bounded Chapter Memory）

不把全书喂给模型，每章只携带：

- 上一章正文（用于承接钩子与文风）
- 上一章摘要（2-5 句：新事实、新伏笔、情绪落点）
- 本章需要的状态摘要

章节完成后把摘要写回 `world-state/commits.md` 与章节文件头部；续写时从提交链读摘要，不重读全书。摘要之外再记两项：**客观观察**（不掺解读的事实变化）与 **token 用量**（本章上下文与正文消耗，用于控制预算）。

### 会话记忆的多层渐进式压缩

规划/写作会话的完整对话**不得删除**：追加归档到 `data/workflows/*_session.jsonl`；滚动摘要（工作记忆、最近窗口）单独存 yaml。压缩只压缩摘要层，不删 JSONL 历史；恢复上下文默认保留最近 24 轮，预算可用环境变量调整。落地到本技能：`plot/decisions.md` 是长期决策归档，`world-state/commits.md` 是章节级滚动摘要，两者都只追加不回改。

## 7. 四级大纲（总纲 → 篇/卷 → 幕 → 节 → 章）

大纲分五层写（Openwrite 的四级大纲扩展为五层，中间插入"总纲"），每层只写本层该有的信息：

| 层级 | 写什么 | 不写什么 |
| --- | --- | --- |
| 总纲 | 一句话故事、核心冲突、最终走向 | 具体情节 |
| 篇/卷 | 本卷目标、起点、转折、卷末钩子 | 逐章细节 |
| 幕 | 推进节拍（升温/对峙/反转/收束） | 台词和描写 |
| 节 | 场景序列、每场戏的节奏角色 | 正文 |
| 章 | 本章目标、关键剧情点、钩子 | 逐句内容 |

好处：改卷不动章，改章不动卷；每章任务书只从"章 + 幕 + 卷"三层取信息。

## 8. 伏笔 DAG（依赖图）

伏笔之间常有依赖：P-B 的揭晓依赖 P-A 先兑现。在 `plot/promises.md` 加依赖字段：

```markdown
| 编号 | 承诺 | 依赖 | 埋下章 | 推进节拍 | 兑现章 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| P-008 | 佩剑的秘密 | P-003 | 12 | 20 | 33 | 推进 |
```

规则：

- 依赖未满足的兑现自动标为**阻塞**，写作指令必须提示。
- 规划时先画依赖边（文字列表或 mermaid 图），再排兑现顺序。
- 同一章兑现的承诺不要超过 2-3 个，避免信息过载。

## 9. 三层风格链（Source → Manifest → Composed）

文风学习升级为三层结构（见 [style-learning.md](style-learning.md)）：

1. **Source pack（拆书笔记）**：样本分析原始记录，每条注明出处、字数、特征证据。
2. **Manifest（风格清单）**：从 source 提炼的可执行规则列表，含量化参数（句长、对话密度）。
3. **Composed（风格说明书）**：最终合成单一风格卡，供每章 Brief 引用。

多源合成规则：主来源定基调，其他来源补充可融合特征；冲突特征显式取舍并记录理由；合成结果仍须遵守"学特征不抄句子"。

## 10. 旧稿导入与整书导出

**旧稿导入**（已有稿件进入本流程）：

1. 一致性体检：扫描人名、时间线、地点、战力等矛盾，产出问题清单。
2. 补状态：按稿件内容回填 `world-state/timeline.md`、`plot/promises.md`、提交链。
3. 建立罗盘与四级大纲（从已有内容反推）。
4. 之后按正常流水线续写。

**整书导出**：

1. 按卷/章顺序合并 `manuscript/` 正文。
2. 生成目录（卷、章标题）。
3. 输出 md 或 txt（去元信息注释），供投稿与发布。

## 11. 审稿维度（可扩展）

Openwrite 使用 37 维审稿；本技能默认用六维审查（爽点/一致性/节奏/OOC/连贯性/追读力）+ AI 味扫描。需要更高强度时，可在六维上扩展细分维度（如伏笔依赖完整性、信息泄漏、场景功能缺失），但阻断项判定不变：**事实矛盾、OOC、漏兑现 = 阻断**。

## 12. 事务感：改动前的安全网

### 运行态锁与回滚

write / multi-write / review 等任何会改文件的阶段共用同一套安全规则：

- **取锁**：同一时刻只允许一个写作任务持有"当前章节"锁（如 `world-state/.chapter.lock`），多任务协作时先取锁、用后释放，防止两个会话同时写一章。
- **备份**：每次批量修改前先备份被改文件（复制到 `备份/`）。
- **回滚**：修改中途失败时回滚到备份，不留半截状态；提交链只记录完整完成的章节，失败任务可在断点处重跑，不重复已可信完成的步骤。
