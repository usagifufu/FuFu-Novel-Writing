# 章节规格（Chapter Spec）与批量自动推进

章节规格是正文生成的**唯一指令源**：写正文前先编译规格，写完后规格归档。规格越清晰，正文越少跑偏，评审越有依据。

## 章节规格模板（YAML）

每个规格文件存 `plot/specs/第XXX章.yaml`：

```yaml
chapter: 101
title: "章节标题"
summary: "200字以内摘要"

before_state:
  characters:
    - {name: "角色A", state: "当前状态", location: "位置"}
  plot_hooks: ["尚未回收的伏笔编号"]

after_state:
  characters:
    - {name: "角色A", state: "章节结束新状态", location: "新位置"}
  plot_advances: ["回收的伏笔", "新埋下的伏笔"]

must_happen:
  - "本章关键事件1（不可跳过）"
  - "本章关键事件2"

tension_curve:
  - {position: 0,  value: 3, note: "承接上章，铺垫"}
  - {position: 50, value: 8, note: "冲突升级/高潮"}
  - {position: 100, value: 5, note: "收尾+新钩子"}

key_scenes:
  - "场景1：一句话概括"
  - "场景2：一句话概括"

new_hooks:
  - "结尾钩子描述"

style_notes:            # 可选：本章风格引用（风格卡条目）
  - "对话比例偏高"
  - "节奏快，短句为主"
```

## 规格生成规则

1. **输入**：前 3 章规格（自动查找）+ 大纲窗口 + 相关角色卡 + 伏笔状态 + 罗盘。
2. **连贯性检查**：读前 3 章规格，验证人物状态、场景位置一致；检测剧情冲突/重复。
3. **信息控制**：写明读者知道什么、主角知道什么、必须隐瞒什么。
4. **承诺衔接**：本章应兑现的伏笔编号写进 `must_happen` 或 `after_state.plot_advances`；新伏笔先登记 `promises.md` 再写进 `new_hooks`。

## 批量自动推进流程

用户说"推进 N 章" / "写第 5-15 章" / "继续往下写 5 章"时执行。脚本：`python scripts/auto_write.py <章节数> [起始章节]`（纯文档型骨架，AI 承担正文生成；需 pyyaml，缺失时降级 JSON）。

```
1. 确定起始章节（正文目录最新章节号 + 1，无正文则从第 1 章）
2. 循环 N 次：
   2.1 更新设定（从上一章 spec 提取新角色/伏笔/场景 → 提示补充）
   2.2 章节规划（生成下一章 spec，读前 3 章做连贯性检查）
   2.3 正文生成（按 spec + 风格卡写 3000-5000 字）
   2.4 评审（五角色评分，P0 必须修）
   2.5 自动修订（<85 分或 P0 → 按反馈修订，最多 2 次）
   2.6 达标 → 提交链入账，进入下一章
3. 输出完成报告（目标/成功/跳过 + 伏笔追踪 + 文件位置）
```

### 配置默认值

| 选项 | 默认值 |
|-----|------|
| 每章字数 | 3000-5000 字 |
| 评审阈值 | ≥85 分 |
| 最大修订次数 | 2 次 |
| 章节间确认 | 否（自动），用户可喊"暂停" |

### 输出报告模板

```markdown
# 批量写作完成报告
- 目标章节：5章（第6-10章）
- 成功完成：4章 / 跳过：1章（问题过多）

### 第6章 ✓ 88/100（3200字）评审通过
### 第7章 ⚠️ 82/100 → 修订后87/100（1次修订后通过）

## 伏笔追踪
- 已回收：3个 | 新增埋下：5个

## 文件位置
- 规格：plot/specs/ | 正文：manuscript/ | 评审：审查报告/
```

## 注意事项

1. **进度保存**：每完成一章立即写入提交链，中断不丢。
2. **冲突检测**：自动检测人物状态/时间线冲突（对照 world-state/timeline.md）。
3. **可中断**：用户说"暂停"即停止，已完成章节保留。
4. **AI 不静默改稿**：修订展示 diff 或说明改动理由；涉及已批准设定的修改先经确认门。
