# FuFu小说助手 技能使用教程

本教程对应技能已安装版本（2026-08-01）。技能融合了 NeuroBook、Webnovel Writer、MuMu-AINovel、Openwrite 方法论与番茄小说下载器，核心思想是：**写长不靠记忆，靠文件**——设定、剧情、正文、世界状态、提交链全部是项目里可见的文件，AI 负责执行与记录，作者负责拍板。

## 1. 怎么触发

在新会话中直接描述需求即可自动匹配本技能，例如：写小说、开新书、写长篇；大纲 / 剧情 / 伏笔 / 人设 / 世界观 / 战力体系规划；拆书、题材研究、追读力 / 爽点设计；文风学习、风格提取、模仿文风、范文下载、网文下载；润色修稿、设定矛盾、项目体检、AI 味检查、旧稿导入、整书导出。

## 2. 三种工作模式

动稿前先确认用户意图，默认不擅自写文件：

| 模式 | 行为 |
| --- | --- |
| 讨论 | 只出主意、查资料、给建议，不改任何文件 |
| 计划 | 先输出完整方案（大纲、任务书等），批准后才执行 |
| 执行 | 按已批准方案动手写文件 |

用户说"直接写"才进执行模式；否则默认先给方案。

## 3. 完整操作流程

### 阶段 1：灵感与题材研究（可选）

开书前扫一轮**题材雷达**：热度、供给、爆款共性、读者预期、差异化。从 37 类网文题材简表选主题材并考虑复合（主题材定调，冲突时主题材优先）。选定后选一本同题材代表作做**拆书**：

1. 结构拆解：前三章钩子、卷节奏、章节节奏。
2. 伏笔拆解：埋/推/兑时间线、间隔规律、依赖关系。
3. 爽点与情绪拆解：钩子类型统计、爽点密度、微兑现案例。
4. 人设拆解：主角动机/缺陷/秘密/弧光、金手指代价、配角功能。
5. 提炼手法清单：适用场景 + 具体做法 + 示例出处，沉淀进 `经验库.md`。

题材拍板写入 `plot/decisions.md`（D-001），作为后续一切设定的前提。

### 阶段 2：文风学习（可选）

没有样本时先用番茄小说下载器获取平台范文（Web UI：`Tomato-Novel-Downloader.exe --server`，浏览器打开 `http://127.0.0.1:18423/` 搜索下载 txt/epub）；已有样本直接分析。完整链路：

```text
1. 获取样本（1-3 个文件，每个建议 ≥2000 字，标注来源与用途）
2. 整理语料：python scripts/prepare_samples.py <下载目录或文件> -o 风格资料/sources
3. 量化统计：python scripts/style_analyze.py 风格资料/sources/*.md
4. 通读提炼：词汇 / 句式 / 描写 / 对话 / 节奏 / 叙述 六维
5. 三层风格链建档：Source pack（拆书笔记）→ Manifest（规则+量化参数）→ Composed（最终风格卡）
6. 试写校准：试写 300-500 字对比，确认保留/加强/去掉
7. 定稿入档：lorebook/风格卡.md，每章 Brief 引用
```

风格卡头部注明三模式之一：`generic`（内置通用规则）/ `extracted`（仅样本提取）/ `hybrid`（合成，默认推荐）。纪律：**学特征不抄句子**，输出不含样本原文片段；下载内容仅供个人学习研究，不转载不商用。

### 阶段 3：项目初始化

```powershell
python scripts/init_novel.py <项目目录> --title <书名> --calendar gregorian
```

历法可选 `gregorian`（公历）/ `simple`（简化纪年）/ `custom`（架空历法）。初始化后目录结构：

```text
<项目目录>/
├── lorebook/         稳定设定（world.md、characters/、风格卡.md、locations.md）
├── manuscript/       正文（000-大纲.md、001-卷名/001-章名.md）
├── world-state/      动态真相源（calendar/subjects/timeline/commits）
├── plot/             剧情层（罗盘/structure/promises/decisions）
├── 经验库.md          项目长期记忆
├── 审查报告/          每章六维审查报告
└── 备份/             正文备份
```

### 阶段 4：项目搭建（五阶段）

1. **项目定位**：一句话故事核心（主角 + 目标 + 障碍 + 代价）、题材与复合题材、读者预期、篇幅。
2. **世界书框架**：世界观规则、势力、地点、力量体系写入 `lorebook/world.md`。
3. **角色设计**：动机、缺陷、欲望、秘密、弧光写入 `lorebook/characters/`；等级体系用统一相对刻度（如 1-100）防战力崩坏。
4. **创作罗盘**：`plot/罗盘.md` 四栏——长期承诺（不可动摇）、近期焦点（本卷目标）、必须保留（读者已记住的）、必须避免（红线）。
5. **世界状态建档**：确定历法与时间起点，登记开局主体状态。

### 阶段 5：世界状态与提交链

`world-state/` 是动态真相源，采用"时间线 + 切面"事件溯源：**不存当前状态，只存按时间排列的变更记录**。状态 = 该时刻之前所有切面推算的结果。

- `calendar.md`：历法策略（全书只用一种时间表达）。
- `subjects.md`：主体登记（人物/门派/王国），只列影响后续一致性的属性。
- `timeline.md`：切面时间线，四种操作（replace / increment / remove / append），**只追加不回改**，写错就新加一条变更记录。
- `commits.md`：章节提交链，每章一条：章号、新事实、本章摘要、审查状态、备份位置。

示例切面：

```markdown
| 时间 | 主体 | 变更 | 来源 |
| --- | --- | --- | --- |
| 第 1 章后 | 林澈 | 左臂被断剑划伤（轻伤） | 001-卷名/001-章名.md |
| 第 1 章后 | 林澈 | 获得佩剑"霜华" | 001-卷名/001-章名.md |
```

规则：只记会影响后续一致性的变更；数值（国库、战力等级）一律在 timeline 增减，正文禁止空降数值；读写分权——规划阶段可读写，正文写作阶段只读，新事实先标草稿、确认后再回补。

### 阶段 6：剧情规划

`plot/` 下四份文件：

- **罗盘.md**：方向锚，规划与动笔前必读；与罗盘冲突的新灵感先记待办，不擅自改主线。
- **structure.md**：四级大纲（总纲 → 篇/卷 → 幕 → 节 → 章，每层只写本层信息）+ 两棵树（承载树管"在哪讲"，因果树管"为什么发生"）+ 章节关系图谱（每章记回应/埋设/关系类型，多时画 mermaid）。
- **promises.md**：承诺账本（伏笔 = 对读者的欠债），登记埋下章/推进节拍/兑现章/状态；可加依赖列构成伏笔 DAG（依赖未满足 = 阻塞，不得强行揭晓）；感情线发糖、爽点间隔也登记为承诺防超期。
- **decisions.md**：ADR 式决策记录（决定/动机/风险/状态），推翻旧决策必须留痕，罗盘更新也在此记录。

每章规划时确定**信息控制**四组：读者知道 / 主角知道 / 必须隐瞒 / 只能暗示。四组全空不许开工。

### 阶段 7：章节写作流水线（每章循环）

1. **预检**：项目健康检查（目录、时间线、承诺账本、最后一条提交存在），对齐罗盘。
2. **任务书（Brief）**：编译写作指令——本章目标、关键剧情点、视角人物、世界锚点、开头/收尾要求、信息控制、应兑现承诺、禁写事项、罗盘对齐、字数、风格卡。上下文按 **canonical packet** 最小组装：本章大纲窗口 + 出场角色卡 + 相关世界规则 + 伏笔状态 + 上一章正文与摘要 + 时间线切面 + 风格卡 + 罗盘；规划侧交接物（author_intent / current_focus）随包进入。
3. **起草**：只写已批准事实；严格视角纪律；新伏笔先登记再写；动态状态必须查 timeline，不凭记忆编造。
4. **六维审查（可阻断）**：爽点 / 一致性 / 节奏 / OOC / 连贯性 / 追读力。**事实矛盾、OOC、漏兑现 = 阻断项必须修**；其余给建议由作者定。需要时可扩展细分维度（伏笔依赖完整性、信息泄漏等）。
5. **去 AI 味终检**：`python scripts/novel_lint.py <正文文件>` 静态扫描 + 语境复核，修复计划先展示、批准后再改。
6. **提交与备份**：新事实追加进 timeline → 承诺状态同步 → commits.md 写提交 → 正文备份到 `备份/` → 2-5 句本章摘要写回提交链与章节头部（有界章节记忆，续写只读上一章正文 + 摘要）。

中途失败可**断点续跑**：已可信完成的步骤不重做，从失败点继续。

### 阶段 8：评审、体检与迭代

- 每章结束给四态报告：已完成 / 部分完成 / 需要你处理 / 未完成，固定三段（产物与完成情况、问题与耗时、下一步建议）。
- 定期**项目体检**：对照时间线、承诺账本、提交链、经验库检查一致性，到期伏笔是否积压。
- **经验库**：拆书所得 + 本书实证（标注章号），写前注入、写后沉淀。
- **会话记忆**：完整对话归档到 `data/workflows/*_session.jsonl`（只追加），滚动摘要单独存 yaml，恢复上下文默认保留最近 24 轮。

### 辅助功能

- **旧稿导入**：一致性体检（扫描人名/时间线/战力矛盾出问题清单）→ 回填 world-state 与承诺账本 → 反推罗盘与四级大纲 → 进入正常流水线。
- **整书导出**：按卷/章顺序合并正文、生成目录、输出 md/txt（去元信息注释）。
- **状态查询**：从 timeline 推算当前状态，或用 `rg` 关键词检索设定，不凭记忆。

## 4. 命令速查

| 命令 | 用途 |
| --- | --- |
| `python scripts/init_novel.py <目录> --title <书名> --calendar simple` | 初始化项目 |
| `python scripts/prepare_samples.py <下载目录或txt> -o 风格资料/sources --split 20` | 整理下载小说为语料 |
| `python scripts/style_analyze.py 样本1.md 样本2.md --name 某某文风` | 文风量化统计 |
| `python scripts/novel_lint.py manuscript/001-卷名/001-章名.md --json` | AI 味静态扫描 |

## 5. 必须守住的纪律

1. **确认门**：对已批准资产（设定/大纲/正文/罗盘）的任何修改，先给 diff 预览（`old_text -> new_text` 精确补丁），确认才落盘；AI 不静默改写。
2. **单一真源**：每条事实只有一个确认版；src（lorebook/plot/manuscript）与运行态（world-state）冲突时列出由作者裁决。
3. **只追加不回改**：timeline 是切面事件溯源，写错就新加变更记录，不删历史。
4. **规划写作分家**：规划角色只定方向，写作角色只按已批准方案写正文；结构问题记阻塞项退回规划，不边写边改大纲。
5. **多任务锁**：同一时刻只允许一个写作任务持有当前章节锁（`world-state/.chapter.lock`）；改大纲/图谱带 `revision` 防冲突。
6. **视角纪律**：只呈现视角人物所知所见；"必须隐瞒"的内容只能暗示或完全不提。
7. **承诺纪律**：到期伏笔必须收线，新伏笔先登记再写，依赖未满足不强行揭晓。
8. **去 AI 味目标**：不是零命中，而是减掉没有功能的模板负担；把文章改烂而命中清零是失败。
9. **写作硬约束**：禁止句式、禁喻词、客观化叙述等清单全书默认生效（见 [写作约束.md](references/写作约束.md)），豁免需用户明确并留痕。

## 6. 最快上手路径

新会话里说"**用小说创作技能开一本新书**"：技能先走计划模式给方案 → 批准 → 初始化项目 → 建立罗盘 → 规划前三章 → 逐章写作 + 审查 + 提交。任何环节可随时要求"项目体检"或"导出全文"。
