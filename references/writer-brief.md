# 章节写作指令（Chapter Writer Brief）

每章开工前先编译本章写作指令。Brief 就绪（关键剧情点、信息控制、世界锚点齐备）再写正文。

## Canonical Packet 上下文组装

写每章前，把写作上下文压缩成最小组装包（见 [openwrite-core.md](openwrite-core.md)）：

1. **当前章大纲窗口**：`plot/structure.md` 中本章及前后 1-2 章的要点（四级大纲的卷/幕/节/章窗口）。
2. **相关角色卡**：本章出场角色的卡（`lorebook/characters/`），只装出场者。
3. **世界规则**：本章涉及的力量体系、地点、势力规则（`lorebook/world.md`、`locations.md` 的相关条目）。
4. **伏笔状态**：`plot/promises.md` 中与本章相关的承诺（应兑现、可推进、依赖阻塞项）。
5. **上一章正文与摘要**：有界章节记忆——只带上一章正文和 2-5 句摘要，不重读全书。
6. **真相文件**：`world-state/timeline.md` 与本章相关的切面。
7. **风格卡**：`lorebook/风格卡.md`。
8. **创作罗盘**：`plot/罗盘.md`，任务书里写"罗盘对齐"。

组装原则：只装本章需要的最小集合；同一事实以单一真源为准；装不下的细节留路径，用时再查。

## Brief 模板

```markdown
## 第 N 章 Brief

- 本章目标：2-3 句，写清本章要完成什么（推进哪条线、达成什么转折）。
- 关键剧情点：
  1. ...
  2. ...
- 视角人物：XXX（全章唯一视角，除非明确说明）
- 世界锚点：时间（历法表达）/ 地点 / 出场角色（对照 world-state 与 lorebook）
- 开头要求：入章方式（回应上章钩子 / 冲突中 / 悬念 / 对话中……）
- 收尾要求：章末钩子类型与情绪落点（悬念 / 威胁 / 情绪 / 信息）
- 信息控制：
  - 读者知道：...
  - 主角知道：...
  - 必须隐瞒：...
  - 只能暗示：...
- 应兑现的承诺：P-XXX（到期项必须收线）
- 可埋下的伏笔：新承诺先登记到 promises.md 再写
- 禁写事项：不得让角色知道 X；不得提前解开 P-YYY；不得出现数值 Z
- 禁写事项（默认叠加全书写作硬约束）：禁止句式/禁喻词/客观化等清单，见 [写作约束.md](写作约束.md)，豁免需用户明确
- 罗盘对齐：本章服务哪个近期焦点 / 守住哪些长期承诺 / 避免哪些红线
- 字数：目标字数与上限（写后核对实际字数）
- 风格卡：引用项目风格设定（见下）
```

## 风格卡（自定义写作风格）

项目里维护一张风格卡（`lorebook/风格卡.md`），每章 Brief 引用。风格卡可以手写，也可以走**文风学习**流程从样本文件统计提炼（见 [style-learning.md](style-learning.md)，多源样本走三层风格链合成）：

```markdown
## 风格卡
- 基调：热血 / 轻松 / 压抑 / 冷峻
- 句长：偏短促 / 偏绵长 / 长短混排
- 描写密度：动作优先 / 氛围优先 / 心理优先
- 对话风格：直白 / 含蓄 / 毒舌；人物口头禅
- 用词：避免的词、偏好用词
- 节奏：快（短场景连击）/ 慢（细节铺陈）
- 其他：梗密度、方言、称谓习惯
```

风格卡不写死：每章可根据剧情功能微调，但基调性参数（句长、描写密度）不要章章乱跳。

## 默认写作约束（硬禁令）

全书默认生效一套写作硬约束：禁止句式与禁喻词清单、客观化中立化叙述、禁止平衡句式与惰性状态词等，见 [写作约束.md](写作约束.md)。每章 Brief 的"禁写事项"自动叠加本清单；用户明确豁免时仅限该处并记录理由；风格卡与本清单冲突时默认本清单优先。

## Writer 执行规则

1. **只写已批准的事实**。动态状态先查 `world-state/timeline.md`，不凭记忆编造伤势、位置、物品、数字。
2. **视角纪律**：只呈现视角人物的所知、所见、所感；未授权信息不得泄漏；"必须隐瞒"的内容只能暗示或完全不提。
3. **承诺纪律**：本章应兑现的伏笔按计划收线；本章新埋的伏笔写进正文后立即登记；不得提前兑现未来承诺；依赖未满足的承诺不强行揭晓。
4. **对话与动作**：角色说话符合人设卡（动机、缺陷、语气习惯）；避免"所有人都用同一腔调说话"。
5. **节奏纪律**：按本章规划的节奏角色推进；有爽点/微兑现任务时在规划位置落点。
6. **写后自查**：正文中产生的新事实列出来，供评审环节回补 world-state。

## 黄金三章（开局模式）

前三章决定读者是否留下：

- **第 1 章**：冲突前置。第一章内出现一个让主角（或读者）不能回头的事件；立住主角性格与一个核心钩子。
- **第 2 章**：让读者看见主角真正想要什么，并展示障碍的成本；加深核心钩子，可引入第二个悬念。
- **第 3 章**：完成开局承诺的第一次小兑现（给读者一个甜头/答案），同时打开更大的问题。

开局写作指令里必须包含：核心钩子是什么、前三章各自要兑现的最小承诺、必须隐瞒的世界级秘密。

## 六维审查（写完每章后）

1. **爽点**：本章有无情绪回报？是否兑现了规划中的小爽点/微兑现？读者读完后有点开下一章的冲动吗？
2. **一致性**：姓名、伤势、位置、时间线、战力等级与 world-state 是否一致？有没有"上一卷断掉的手臂这卷长回来"的吃书？
3. **节奏**：张弛是否失衡？连续压抑或连续爽导致疲劳？和本章规划的节奏角色（推进/蓄力/转折/余波）是否相符？
4. **OOC**：角色行为、语气、决策是否符合人设卡与动机？有没有"为了让剧情走，角色突然变蠢/变狠"？
5. **连贯性**：本章开头是否回应了上一章钩子？章间逻辑链（回应/埋设）是否闭合？
6. **追读力**：本章钩子是否立住？承诺账本有无新到期项？债务是否积压？

判定标准：**事实矛盾、OOC、漏兑现 = 阻断项**，必须修完再提交；润色、节奏建议 = 非阻断，给方案由用户定。需要更强审查时可扩展细分维度（伏笔依赖完整性、信息泄漏等），阻断项判定不变。

## 提交前检查

- 信息控制是否被泄漏？让"必须隐瞒"的内容进入角色的嘴或心理活动 = 硬伤。
- 承诺账本是否更新？本章埋/推/兑的承诺与 promises.md 一致；依赖阻塞项是否已提示。
- 世界状态是否回补？新事实是否已在 timeline.md 追加、提交记录是否写入 commits.md。
- 本章摘要（2-5 句：新事实、新伏笔、情绪落点）是否写入提交链与章节文件头部（有界章节记忆）。
- 视角是否漂移？有没有跳到其他角色的心理或读者全知视角。
- 写作硬约束对照：禁止句式、禁喻词、平衡句式、惰性状态词、程式化情绪描述是否混入正文（见 [写作约束.md](写作约束.md)）。
- AI 味扫描：跑 `scripts/novel_lint.py`，结合语境复核（见 llmlint.md）。
- 备份：正文复制到 `备份/`，审查结论写入 `审查报告/`。
