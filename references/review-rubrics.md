# 多视角对抗式审查（Review Rubrics）

章节正文写完后，用多视角对抗式审查找问题——**审查是找问题，不是验证正确性**。目标是把每个视角的盲区补上，输出可执行修改建议。

## 五角色评审（加权评分）

| 角色 | 关注点 | 权重 |
|-----|-------|------|
| 阅读者 | 开篇吸引力、节奏、画面感 | 25% |
| 编审 | 错别字、病句、一致性 | 25% |
| 故事家 | 剧情逻辑、伏笔、钩子 | 25% |
| 文学顾问 | 语言艺术、人物刻画 | 15% |
| 毒舌读者 | 套路化、水文、毒点 | 10% |

**评分档位**：

| 分数 | 等级 | 处置 |
|-----|------|------|
| 90-100 | 精品 | 通过 |
| 85-89 | 优秀，可发布 | 通过 |
| 75-84 | 良好，小改可发 | 建议修订 |
| 60-74 | 合格，需修改 | 必须修订 |
| <60 | 不合格 | 重写 |

> 批量写作时默认阈值：≥85 通过，最多自动修订 2 次，2 次仍不达标标记问题继续下一章。

## 红线分级规则

### P0 - 绝对禁止（阻断项，必须修）

| 禁止项 | 说明 |
|-------|------|
| 明显 AI 词汇 | "众所周知"、"不言而喻"、"总而言之"等 |
| 感悟式结尾 | "他明白了..."、"她终于懂得..." |
| 感叹式结尾 | "真是太..."、"多么..." |
| 上帝视角 | "所有人没想到..."、"全书第x章..." |
| 事实矛盾 / 吃书 | 与已入账世界状态冲突 |
| OOC | 角色行为脱离人设 |
| 抄袭级错误 | 与经典作品高度重复 |

### P1 - 建议避免

| 避免项 | 说明 |
|-------|------|
| 套路化表达 | 网文老梗堆砌 |
| 流水账 | 无意义的情节推进 |
| 抽象心理 | "他感到很..."、"她觉得..." |
| 排比句 | 连续相同句式 |
| 代词开头 | 连续"他/她/它"开头 |

### P2 - 可选优化

| 优化项 | 说明 |
|-------|------|
| 细节打磨 | 动词更精准 |
| 画面强化 | 更多感官描写 |
| 节奏调整 | 张力起伏更明显 |

## 四视角对抗式审查（Agent 模式）

已部署 reviewer agents 时并行 spawn，缺失/异常自动降级 solo：

| 视角 | 职责 |
|------|------|
| story-architect | 结构审查：大纲对应、节奏、章节关系图谱 |
| consistency-checker | 一致性审查：时间线、人物状态、设定、承诺账本 |
| prose-editor | 文字审查：语言、句式、AI 味、病句 |
| reader-advocate | 读者视角：爽点密度、追读力、毒点 |

- `full`：spawn 全部 4 个 Agent
- `lean`：spawn story-architect + consistency-checker
- `solo`：当前会话直接执行，不 spawn

## 审查输出格式

```markdown
# 审查报告：第 N 章
## 五角色评分
阅读者 xx/100 | 编审 xx/100 | 故事家 xx/100 | 文学顾问 xx/100 | 毒舌读者 xx/100
最终得分：xx/100（等级）

## P0 阻断项
- [位置] 问题描述 → 修改建议

## P1 建议项
- [位置] 问题描述 → 修改建议

## P2 优化项
- [位置] 问题描述 → 修改建议

## 结论
通过 / 修订后通过（第x次） / 不通过需重写
```

## 与流水线的衔接

- 六维审查（爽点/一致性/节奏/OOC/连贯性/追读力）是本技能主审查框架；本文件提供评分量化与角色分工，两者互补。
- 事实矛盾、OOC、漏兑现承诺 = 阻断项，必须修；其余按 P1/P2 给建议。
- 审查报告存档到 `审查报告/第XXX章.md`，结论同步写入提交链。
