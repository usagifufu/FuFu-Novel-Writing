# 项目结构规范

## 目录布局

```text
<项目目录>/
├── 文件布局.md                  # 本项目的布局声明（可选；写下实际采用的偏差）
├── lorebook/                    # 稳定设定：不随剧情改变（src 确认版）
│   ├── world.md                 # 世界观规则、历史、力量体系
│   ├── characters/index.md      # 角色卡：动机、缺陷、欲望、秘密、弧光
│   ├── 风格卡.md                # 文风档案（手写或从样本文件提炼）
│   ├── 文风模仿要求.md          # 全文级文风总纲（可选；见文风学习）
│   └── locations.md             # 地点与势力（静态部分）
├── manuscript/                  # 正文（已批准部分 = src）
│   ├── 000-大纲.md              # 全书大纲（承载树骨架）
│   └── 001-卷名/001-章名.md     # 卷 → 章，每章一个文件
├── world-state/                 # 动态世界状态：随时间演化的运行态真相源
│   ├── calendar.md              # 历法策略
│   ├── subjects.md              # 主体登记与关键属性（只保留当前值，可刷新）
│   ├── timeline.md              # 切面时间线（只追加，不回改；事实源头）
│   └── commits.md               # 章节提交链（每章一条：章号、事实、摘要、审查、备份）
├── plot/                        # 剧情层
│   ├── 罗盘.md                  # 创作罗盘（长期承诺/近期焦点/必须保留/必须避免）
│   ├── structure.md             # 四级大纲 + 承载树 + 因果树 + 章节关系图谱
│   ├── promises.md              # 承诺账本（伏笔/节奏承诺 + 伏笔 DAG + 时间线）
│   ├── decisions.md             # 创作决策记录（ADR）
│   ├── specs/                   # 章节规格（产出物）：正文唯一指令源
│   │   └── 第001章.yaml
│   └── briefs/                  # 写作任务书（产出物）：每章一份
│       └── 第001章-brief.md
├── 经验库.md                    # 项目长期记忆（写法、钩子、节奏心得）
├── 审查报告/                    # 每章六维审查报告
└── 备份/                        # 章节正文备份（提交与批量修改前生成）
```

## 按读写权限分层

内容分区（lorebook / manuscript / world-state / plot）解决"东西放哪"。还有一条正交的主轴：**每个区能不能改**。两者要一起看：

| 区 | 目录 | 权限 | 判据 |
| --- | --- | --- | --- |
| **src · 确认版** | `lorebook/`、`plot/`、`manuscript/` 已定稿部分 | **可改，但每次都走确认门** | 已批准、不再被推导覆盖的内容 |
| **运行态** | `world-state/` | **只追加，永不回改** | 随剧情推导变化的事实流水 |
| **产出物** | `plot/specs/`、`plot/briefs/`、`审查报告/`、`备份/` | **只增不改** | 一章一份，写完即冻结 |
| **例外层** | `经验库.md` | 可增可改 | 拆书所得与本书实证的合流处 |

行为后果，三条最容易踩的：

- 改 `lorebook/characters/index.md` → **先出 diff 给用户看，确认后落盘**
- 往 `world-state/timeline.md` 追加切面 → **不用问，那是只追加区**
- 改 `plot/specs/` 里已写完的规格 → **不允许**。要改就另起一份，规格是当时决策的快照

## 单一真源与运行态

每一条事实只有一个确认版（见 [openwrite-core.md](openwrite-core.md)）：

- **src（确认版）**：`lorebook/`、`plot/`、`manuscript/` 中已批准的内容。改它们必须走确认门（diff 预览 → 用户确认 → 落盘）。
- **运行态**：`world-state/`。写正文时查它，写完后把新事实追加回去；运行态只追加不回改。

冲突处理：src 与运行态说法不一致时，列冲突、由用户裁决，AI 不得自行改 src。

## 稳定 vs 动态判据

问："这个东西会随剧情改变吗？"

- 会变 → `world-state/timeline.md`（状态切面）。
- 不会变 → `lorebook/`（设定圣经）。

典型归属：

| 内容 | 归属 |
| --- | --- |
| 世界规则、魔法体系、历史大事件 | lorebook/world.md |
| 角色的出身、性格底色、长期目标 | lorebook/characters/ |
| 角色当前位置、伤势、物品、关系现状 | world-state/timeline.md |
| 势力当前强弱、国库、边界 | world-state/timeline.md |
| 等级/境界序列与战力换算刻度 | lorebook/world.md |
| 句长、对话密度、描写偏好等文风参数 | lorebook/风格卡.md |
| 本书不可动摇的核心与红线 | plot/罗盘.md |
| 伏笔与兑现计划（含依赖关系） | plot/promises.md |
| "为什么让主角黑化" | plot/decisions.md |
| 每章新事实入账审计与章节摘要 | world-state/commits.md |
| 验证有效的写法/钩子/节奏手法 | 经验库.md |

## 每章产物流水线

写一章 = **产生 4 个新文件 + 回补若干处**（具体数字随项目，下面是最小集）：

```text
①  plot/specs/第N章.yaml              章节规格（唯一指令源）
②  plot/briefs/第N章-brief.md         写作任务书（信息控制四组是硬门）
③  manuscript/卷号-卷名/NNN-章名.md    正文
④  审查报告/第N章-审查.md              六维审查结论
⑤  备份/NNN-章名.md                   正文快照（与正文同名）

回补（就地更新，不产生新文件）：
   world-state/timeline.md   追加本章切面
   world-state/subjects.md   刷新当前值
   world-state/commits.md    追加 C-00N
   plot/promises.md          更新伏笔状态
   plot/decisions.md         有新决策才写
   经验库.md                 有验证有效的写法才写
```

**规格与任务书是两个东西**，不要合并：spec 是结构化 YAML（状态变迁、必发事件、张力曲线），Brief 是给人读的指令（信息控制四组、禁写事项）。`chapter-spec.md` 管前者，`writer-brief.md` 管后者。

## 命名规则

| 目录 | 命名格式 | 示例 |
| --- | --- | --- |
| `plot/specs/` | `第NNN章.yaml` | `第001章.yaml` |
| `plot/briefs/` | `第NNN章-brief.md` | `第001章-brief.md` |
| `manuscript/` | `NNN-卷名/NNN-章名.md` | `001-记录员/001-三个字.md` |
| `审查报告/` | `第NNN章-审查.md` | `第001章-审查.md` |
| `备份/` | `NNN-章名.md`（与正文同名） | `001-三个字.md` |

三条硬规矩：

1. **`specs/` 命名不可改。** `scripts/auto_write.py` 用 `f"第{chapter:03d}章.yaml"` 拼路径，一改自动化就找不到文件。
2. **章名取本章内容的关键词，不用「第N章」。** 章名是给未来的自己看的检索线索。
3. **备份与正文同名。** 复制到 `备份/` 时保持文件名，方便反查；要分版本就加章号前缀。

## 运行态的两套写法（规范内部差异，此处明确）

`openwrite-core.md` 说"运行态只追加，不回改历史"，但 `world-state/subjects.md` 装的是**当前状态**（当前位置、当前关系、当前暴露面），这个东西**不可能只追加**。所以 `world-state/` 内部实际是两套写法：

| 文件 | 写法 | 说明 |
| --- | --- | --- |
| `timeline.md` | **只追加** | 历史流水，状态修正用新切面表达 |
| `commits.md` | **只追加** | 提交流水 |
| `subjects.md` | **可刷新** | 只保留当前值；变更记进 `timeline.md` |
| `calendar.md` | 基本不变 | 历法定义 |

`subjects.md` 文件头写死这句口径：**变更一律写进 `timeline.md`，本表只保留当前值。**

## 提交链（章节提交）

写完一章不是结束，而是**提交**。在 `world-state/commits.md` 追加一条记录：

```markdown
| 提交 | 章节 | 新事实 | 本章摘要 | 审查状态 | 备份位置 |
| --- | --- | --- | --- | --- | --- |
| C-001 | 001-卷名/001-章名.md | 林澈左臂轻伤；获得佩剑"霜华" | 雨夜截杀立钩，林澈决定追查身世 | 通过 | 备份/C-001-001-章名.md |
```

提交链是"这章写了什么"的审计记录，也是断点续跑的依据：续写时先看最后一条提交，不重复已完成步骤。**本章摘要**（2-5 句）就是有界章节记忆的载体：续写只读上一章正文 + 摘要，不重读全书。

## 长期记忆（经验库）

`经验库.md` 记两类内容：

1. **拆书所得**：从其他作品拆出的手法（钩子类型、爽点密度、伏笔间隔、人设模板）。
2. **本书实证**：本书里验证有效的写法（"第 3 章那个留白读者反馈好"），以及踩过的坑（"战力数值必须走时间线，否则崩"）。

写作前注入相关条目，写作后沉淀新心得；来源标注章号。

## 旧稿导入

已有稿件进入本流程（见 [openwrite-core.md](openwrite-core.md)）：

1. 一致性体检：扫描人名、时间线、地点、战力矛盾，产出问题清单给用户。
2. 补状态：按稿件回填 `world-state/timeline.md`、`plot/promises.md`、提交链。
3. 反推罗盘与四级大纲：从已有内容提炼长期承诺与结构。
4. 之后按正常流水线续写。

## 整书导出

1. 按卷/章顺序合并 `manuscript/` 正文。
2. 生成目录（卷、章标题）。
3. 输出 md 或 txt（去除元信息注释），供投稿与发布。

## 文件写作约定

- 全部使用 UTF-8 Markdown；`plot/specs/` 例外，用 YAML。
- 时间一律用项目历法字符串，例如 `第 372 年 春` 或 `公元 1203 年 7 月`，便于检索与对齐。
- 每章正文文件头部放一行元信息注释：`<!-- 章：001 | 卷：001 | 视角：XXX | 世界时间：... -->`。
- 头部还要放**有界章节记忆摘要**（2-5 句：新事实、新伏笔、情绪落点）。续写下一章时只读上一章正文 + 这段摘要，不重读全书。
- 任何涉及动态状态的段落，写完后检查是否需要在 `timeline.md` 追加切面。
- 每章提交前：正文备份到 `备份/`，审查结论写入 `审查报告/`。

## 可选：项目级布局声明

技能给的是通用布局。项目实际执行中如果加了目录、改了命名、或对某条规范做了有意偏离，建议在项目根写一份 `文件布局.md` 记录**偏差**，不重复抄技能里已有的内容。这份文件属 src 区，改动同样走确认门。

典型要记进偏差声明的东西：

- 规范外新增的目录（如 `plot/briefs/` 落盘后目录名）
- 本项目卷名与章节范围对照表
- `world-state/` 内两套写法的实际采用情况
- 尚未采用的规范项（见下）

## 尚未采用的规范项

技能另有两条可选项，项目可按规模决定是否启用：

| 项 | 建议 | 启用时机 |
| --- | --- | --- |
| **世界关系图谱** | 单一真源 `lorebook/relations.md`，人物/势力/物件关系不分散在各角色卡 | 角色数量增长到 10+ 人时 |
| **TOML front matter** | 核心设定文档用 `id`/`summary`/`tags`/`detail_refs`/`related` | 跨文档引用变多时 |

## 命名

- 卷/章目录与文件用三位数字前缀保证排序：`001-卷名/001-章名.md`。
- 角色、地点、势力使用统一名称；设定补全时先检索已有条目，避免同名异义。
